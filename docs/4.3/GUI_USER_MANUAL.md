# 自转周期测量 GUI 用户手册

[English README](../../README_EN.md) | [项目首页](../../README.md)

本文面向第一次使用本项目 GUI 的用户，说明项目原理、界面操作、参数含义、配置注意事项和常见问题。GUI 入口为 `pyside_gui.py`（或 `python -m rotation_gui`）。

Chirp 的独立反演开关、旧配置兼容与八组合报告统一见[第8.1—8.2节](#optional-period-methods)。

## 1. 项目原理概览

本项目用于构造一条“小行星雷达回波仿真到自转周期反演”的端到端流水线。流水线由三个相互独立的子模块组成，模块之间通过文件交换数据：

1. `observation/`：根据目标、发射站、接收站和接收时间轴，解算三事件光行时几何，输出 `observation_info.npz`。
2. `echo/`：读取观测几何和目标形状模型，计算旋转小行星的复基带 I/Q 回波，输出 `echo/echo.npz`。
3. `inversion/`：读取仿真回波，计算动态频谱和特征序列，用 Lomb-Scargle 周期搜索估计自转周期，输出 `inversion/summary.json`、`best_summary.json` 和图像。

GUI 不改变流水线物理模型。它负责编辑配置、逐阶段启动脚本、显示进度、记录当前会话日志和预览结果。运行前 GUI 会在 `runs/<实验名>/configs/` 下生成本次实际使用的配置快照，便于复查。

## 2. 启动方式

推荐在 Conda 的 `pytorch` 环境中启动：

```powershell
conda activate pytorch
python pyside_gui.py
```

顶部只有一个「图像结果 ▾」入口；点击展开，再次点击同一按钮收起，也可点击外部或按Esc收起。卡片使用与参数区相同的白底、蓝色标题和控件样式，先显示卡片，再在后台读取Run／CPI列表和已有结果状态；读取期间相应按钮暂不可用，完成后自动更新，切换实验或关闭卡片不会把旧查询结果填到新卡片。默认全观测区间，原始／脉压按Run依次排列，灰线标出Run边界，不将相隔数小时的观测空档涂成连续信号；可切换单Run。CPI控件是已完成反演保存的窗口列表，不是时间步长，列出实际有效窗口的Run、脉冲范围和中心时刻。真正CPI时长及步长来自保存的反演参数，无独立看图参数；缺少对应结果时置灰，不启动科学计算。

左侧每个计算阶段在能读到该阶段产物、且参数与产物记录一致时显示「已运行」。改了会影响该阶段的参数后，状态变为「参数修改，需重新运行⚠」。

## 3. 界面区域说明

窗口顶部是配置文件、实验设置、运行按钮和进度条：

- `配置文件`：用不可编辑的灰色文字区显示当前 JSON 路径；路径太长时中间省略，悬停可查看完整路径。无有效会话时默认是 `configs/chirp_point_target_test.json`（开发夹具；正式示例待重新设计）。
- `打开`：选择一个已有 JSON 并载入，实验名初始设为该文件名。
- `保存`：更新当前显示的 JSON 文件。实验名变化不改变保存路径。
- `另存为`：用对话框选择一个新 JSON 路径并保存，随后切换当前配置路径；实验名保持不变。若目标是另一个已有文件，会报错，避免覆盖。
- `校验`：按当前阶段检查配置。
- `发射波形`：位于实验设置行，决定 CW 或 chirp 处理分支。
- `实验名`：`runs/<实验名>/` 的目录名，与配置文件路径独立。不能包含路径分隔符或 Windows 保留字符。
- `输出目录`：运行结果根目录。相对路径会按项目根目录解析。
- `Python`：用于执行各子模块脚本的 Python 解释器。
- `运行当前阶段` / `运行完整 pipeline` / `中止` / `图像结果 ▾`：位于顶部操作行，进度条并排。图像生成期间可以中止，阶段运行结束不自动进行脉压绘图。

左侧是流水线阶段控制：三个阶段按钮及各自状态。点击阶段只切换中间参数页。

中间是阶段参数编辑区。点击左侧阶段按钮可以切换当前编辑的模块参数。每次执行阶段前，GUI 会把当前页面字段同步回配置。观测阶段顶部显示“单基站观测”勾选框，回波阶段顶部显示“散射模型”选择框。

观测页卡片按目标、测站、接收或发射时序、计划与星历分组。顶部「发射波形」只写入 `echo.waveform.type`，并切换观测事件源：连续波显示接收设置；Chirp 显示发射时序（`observation.transmit` 的 PRF 与脉宽）、雷达体制、接收采样和观测计划。勾选「单基站观测」后隐藏接收站。星历卡片仅在目标为 `horizons_vectors` 时出现。日志在参数区下方，回波预览走外部浏览器。

卡片标题使用浅蓝标题带与深蓝加粗字；“形状模型、散射指数、信噪比”等同级字段使用一致的字体。自转轴、初始坐标、速度、散射指数和斑块方向统一使用纵向关系线表示子模块：模块标题位于左侧，浅色竖线将标题与右侧下属条目分开，条目名称位于输入框上方并纵向排列。
卡片内顶层字段保持一致的竖向间距。数值与单位共用等高边框，可选单位以右侧箭头区分，固定单位沿用相同配色。单位选择仍表示当前输入数值的单位，保存时换算为标准单位。
数值编辑器会立即标红非数值、无穷值或非整数计数；此类草稿不能保存、切换阶段或运行。坐标分量允许输入 `299,792,458` 形式的千分位分隔符。

滚动条采用深色滑块与浅色轨道。所有布尔参数统一使用勾选框：选中时为蓝底白勾，未选中时为白底深边框，不再使用“是/否”下拉框。下拉列表按控件位置展开，不再以当前选项作为弹出位置锚点；只有屏幕底部空间不足时才向上展开。Windows 下优先使用原生样式及其展开动画，系统不支持该效果时直接显示列表。

回波页左栏为计算设置与雷达参数，右栏为目标参数与散射特性。点目标模式下隐藏形状、自转和散射热点字段。
「雷达参数」包含载频、Chirp 带宽/基带约定和幅度。「噪声」是独立卡片：勾选「添加噪声」后显示信噪比与噪声种子，交互对齐「散射特性」。反演页分为「时频分析」和「周期搜索」。
Chirp 基带约定的新建默认值为“对称带宽”（`centered`）；加载已有配置时保留其中显式指定的约定。
这些都是显示分组，另存 JSON 时仍使用原有字段路径。

观测计划的“选时方式”提供“手动选择”和“自动选取”。自动选取时显示 Run 数量、单次 Run 时长、“包含非可见时段”和“随机选取”；勾选随机选取后才显示随机种子。保存时只写出当前选时方式的活动字段：手动只留 `runs`，等间隔留 `run_count`/`run_duration_s` 且不含种子，随机才写 `random_seed`。互斥草稿可以留在界面内存中，不会进入规范 JSON。非可见时段选项写入 `visibility.allow_unobservable_for_simulation`。

自动选取下方的观测计划预览先检查单次 Run 能否在首个有效回波返回前完成脉冲发射、收发切换和安全余量，再给出**近似可排列**的 Run 数量上限；该上限来自近似传播时延，不表示正式计划已通过光行时解算。单站跨 Run 收发冲突会在预览中按与正式解算相同的区间判据标为不可行。单次 Run 自身不可行时数量上限直接显示为 0，并给出建议的 `run_duration_s` 上界。预览包含“可见性”“Run”和“ADC 估计”三条轨道。大地坐标测站用绿色和红色分别表示满足与不满足高度角约束的时段；自定义直角坐标测站不定义本地地平，可见性轨道按整段候选时间着色，详情写“自定义直角坐标：不应用地平可见性约束”，不会改用灰色斜纹。灰色斜纹只表示“当前坐标本应计算几何可见性，但本次计算失败”。深蓝色表示发射 Run，浅蓝色表示包含传播、切换、安全余量和接收余量的调度预留尾部，紫色表示按当前传播时延估算的 Run 级连续 ADC 窗。极短区间在屏幕上不足一个像素时会保留最小显示宽度，因此轨道用于判断分布与相对关系，精确数值仍以摘要和正式解算结果为准。影响预览的字段变化后，预览块显示“参数已更新，请刷新预览”，只有点击「刷新预览」才重新计算；星历查询同样只在此时发起。测站改用直角坐标后，高度角、可见性采样步长和“包含非可见时段”会从当前配置中移除，不再作为隐藏字段继续影响选时。
发射 Run 的选取原则、单站预留长度、路径变化率时标伸缩和 ADC 窗生成公式见[观测时刻选取与接收窗口生成规范](OBSERVATION_TIME_SELECTION.md)。
切换“随机选取”时，随机种子在勾选项下方增减，当前滚动位置和已达到的滚动范围保持不变，收起后留下的空白可通过向上滚动移出视口。

日志位于参数区下方；进度条和回波预览入口位于顶部运行栏：

- `执行日志`：显示启动命令、配置快照路径、上游产物复用情况、中文警告、错误信息与阶段结果摘要。协议控制行（`__PROGRESS__`、`__WARNING__`、`__ERROR__`、`__SUMMARY__`）一律先解析成可读文本，不会原样出现在日志里；渲染层对文本只做一次 HTML 转义，日志中不会出现 `&quot;` 之类的实体，空行也不会混入不换行空格。每个阶段成功后会列出该阶段产物路径（如 `回波数据：…\echo\echo.npz`）。成功、警告和错误分别用绿、琥珀和红色标示；日志最多保留最近 5000 行，超出部分从最早的记录开始丢弃。标题右侧提供“复制”和“清空”，清空只影响当前窗口显示，不删除已生成的实验文件。
- `原始回波`：默认全场概览；横轴快时间的质心相对延迟ns，纵轴为按Run排列的慢时间脉冲顺序，悬停显示Run、真实脉冲号与时刻。缺测留白，低功率使用45 dB色标。全场显示每Run代表行，保留首尾；显示列按像素缩减取最大功率，计算不抽样。这里的“合并显示列”只是屏幕呈现，不是新的雷达处理，也不改变科学距离分辨率。原始图不调用脉压。
- `脉冲压缩`：只读正式反演保存的脉压检查，不在看图时匹配滤波；默认全场Run顺序。上图是二维脉压，横轴快时间延迟、纵轴脉冲顺序，每一横行对应一条被显示的脉冲回波；下图是全部被选脉冲在完整原行宽上的平均脉压功率。两幅图共享快时间横轴，缩放一幅时另一幅同步，默认聚焦信号并可恢复全记录范围。全场显示缩减不影响已保存均值计算。原生行未经共同轴插值，显示轴使用中位偏移；它是波形检查，不能把裁剪平均值当成完整相关科学矩。
- `实际反演特征` / `逐脉冲检查`：两者只读已完成反演保存的检查产物，缺失时需先运行周期反演。前者显示实际用于搜索的科学观测，后者是逐脉冲三项对照，不等于CPI五项。执行反演时，项目自产的未压缩IQ与valid直接映射原NPZ，压缩外部输入才提取为NPY映射；分块提取完整相关矩，忽略无需消费的clean_iq。Run内连线，Run之间留NaN断点。正常查看这些结果不重新计算。
- `距离—多普勒` / `周期搜索`：前者只读已完成反演保存的全部CPI、完整距离／频率网格的显示数据；二维相对功率dB用单精度保存，一维距离功率与坐标保留双精度，科学特征的计算精度不变。旧版双精度CPI仍可读取。缺产物时按钮置灰，必须通过运行周期反演补齐。单CPI的上图为一维距离功率曲线，横轴相对功率dB、纵轴距离延迟；它来自该CPI的FFT功率沿多普勒求和，不是逐脉冲矩阵，也不能从这条曲线观察窗内各脉冲演化。下图横轴多普勒频率、纵轴距离延迟，每一纵列对应一个频率格的距离功率分布。标题给出Run、脉冲范围、中心时刻和Hann窗；FFT不跨Run。两图默认聚焦中央99%显示能量的延迟范围，可切换全延迟范围。周期搜索只打开上次保存的周期曲线与候选；看图不启动任何反演阶段科学计算。

- 顶部进度条：显示当前子模块的粗略百分比和正在执行的子步骤。

## 4. 推荐使用流程

第一次运行建议先用示例配置跑通：

1. 启动 `python pyside_gui.py`。
2. 保持默认配置和实验名，选择左侧 `观测解算`，点击 `运行当前阶段`。
3. 等待 `观测解算` 完成，查看日志和生成的观测信息。
4. 选择左侧 `回波仿真` 并点击 `运行当前阶段`；完成后从 `图像结果 ▾` 分别选择原始回波或脉冲压缩，按Run查看。
5. 选择左侧 `周期反演` 并运行，查看日志结果摘要；从统一结果卡片打开实际反演特征和周期搜索。完整流水线仍依次重跑三个阶段。
6. 只想在已有回波上重跑反演时，不必重跑前两个阶段：把 `实验名` 与 `输出目录` 指回上次的 run，选择 `周期反演` 后点 `运行当前阶段`。日志会给出 `复用已有回波数据：…\echo\echo.npz`；若该文件不存在，GUI 会在启动子进程前提示应把实验名指向包含 `echo.npz` 的目录。复用依据该 run 的 `stage_manifest.json` 中相关参数摘要、上游状态与文件身份（路径、大小、修改时间），不扫描文件内容计算 SHA256；`*.generated.json` 只是子进程输入，不是复用证据。回波或上游观测的相关参数不匹配、文件身份变化或上游已经重跑时，会要求重跑相关阶段；只改反演搜索范围不会挡住复用回波。缺少阶段参数记录的历史产物仍需要确认，旧哈希字段不再要求逐比特核对。没有新增可选严格核验模式。
7. 在 `runs/<实验名>/configs/` 中检查 `*.generated.json`，确认本次实际参数。

正式实验可以先在 GUI 中打开示例配置，再改参数。要建立自己的配置文件，点「另存为」选择文件名和目录；之后点「保存」更新该文件。修改「实验名」只会改变运行结果的目录，不会创建或改名 JSON。配置路径与实验名可以不同。

```powershell
python pyside_gui.py
```

载入配置时，GUI 会把配置字段更新为该文件中的设置，并将实验名设为文件名（不含 `.json`）。不要直接改 `runs/<实验名>/configs/*.generated.json`，这些是每次运行生成的快照。
退出 GUI 时，当前有效的参数、配置路径、实验名和输出目录保存在 `.gui_state/pipeline_gui_state.json`，下次打开时恢复这次会话；无效状态会被忽略并回退到默认示例配置。会话状态不会自动覆盖原 JSON，只有点击“保存”才写入配置文件。

## 5. 顶层配置结构

顶层 JSON 只有三个业务段：

```json
{
  "observation": {},
  "echo": {},
  "inversion": {}
}
```

`observation_info.npz`、`echo.npz`、`summary.json` 等中间路径不需要手动填写。GUI 和 `pipeline.py` 会自动生成并注入下游模块。

## 6. 观测解算参数

`observation` 决定接收时间轴、目标状态、发射站/接收站状态和三事件光行时求解设置。

### 6.1 `target`

`target` 表示小行星质心状态。GUI 先选择“位置来源”：手动坐标或 Horizons 星历；手动坐标下再勾选是否进行匀速直线运动，与发射站、接收站的运动设置保持一致。目标不提供大地坐标选项。

| 字段 | 含义 | 注意事项 |
| --- | --- | --- |
| `id` | 目标编号或自定义标识 | `horizons_vectors` 模式下是 Horizons 查询目标编号。 |
| `name` | 显示和元数据名称 | 可读即可。 |
| `state` | 保存到配置的状态模型 | 手动坐标且未勾选运动时为 `static`，勾选后为 `linear`；选择 Horizons 星历时为 `horizons_vectors`。 |
| `position_m` | 静态位置，单位 m | `state=static` 时使用。 |
| `position0_m` | 初始位置，单位 m | `state=linear` 时使用。 |
| `velocity_m_s` | 匀速速度，单位 m/s | `state=linear` 时使用。 |
| `object_type` | Horizons 目标类型 | 新配置默认为 `smallbody`；旧配置中显式写入的 `null` 仍可读取。当前实验只使用小天体，因此 GUI 不显示此字段。 |

常用选择：

- `static`：目标固定不动，适合最小测试。
- `linear`：目标匀速直线运动，适合离线仿真和快速验证。
- `horizons_vectors`：从 JPL Horizons 查询目标相对参考位置的星历表，再本地插值，适合真实天体实验。

### 6.2 `transmitter` 和 `receiver`

发射站和接收站支持：

| `state` | 含义 | 需要字段 |
| --- | --- | --- |
| `static` | 用户直接给 Cartesian 坐标 | `position_m` |
| `linear` | 匀速 Cartesian 状态 | `position0_m`、`velocity_m_s` |
| `geodetic_fixed` | 固定经纬高转 ECEF 近似 | `lat_deg`、`lon_deg`、`height_m` |
| `astropy_geodetic` | Astropy 按时间计算 GCRS 测站位置 | `lat_deg`、`lon_deg`、`height_m` |

GUI 不直接展示这四个技术状态，而是先选择“坐标格式”：

- 直角坐标：显示“初始坐标”子模块和“进行匀速直线运动”勾选框。未勾选时保存为
  `static`；勾选后再显示“速度”子模块，并保存为 `linear`。
- 大地坐标：显示包含经度、纬度、高度的“初始坐标”子模块，以及与其并列的
  “随地球自转更新位置”勾选框。勾选时保存为 `astropy_geodetic`，未勾选时保存为
  `geodetic_fixed`。

这里只接受 canonical v4 JSON；旧技术字段或未知字段会显示完整路径并拒绝加载。这里随时间变化的是测站在地心惯性系中的位置，而不是经纬度和高度本身。

真实地面测站优先使用 `astropy_geodetic`。Horizons 的地心参考中心、Earth 参考平面和网络重试策略由 observation 实现内部固定，不是 GUI 配置字段。

`linear` 发射站/接收站用于离线仿真、平台运动或算法验证。它并不表示真实地面站的高精度运动模型；真实固定地面站仍建议使用 `astropy_geodetic`。

观测参数页顶部提供“单基站观测：接收站沿用发射站参数”选项，启动和载入配置后
默认为关闭。勾选后接收站分组会隐藏，保存或执行前 GUI 会把发射站配置深拷贝为
接收站配置。取消勾选后接收站分组重新出现，可以单独配置双/多站几何。切换选项时
会把焦点留在勾选框上，不会再全选顶部配置文件路径。

### 6.3 `receive`

| 字段 | 含义 | 注意事项 |
| --- | --- | --- |
| `start_utc` | 接收起始 UTC | 使用 ISO 格式，例如 `2026-01-01T00:00:00.000`。 |
| `duration_s` | 接收时长，保存单位 s | GUI 可用 h、min 或 s 输入；样本数约为 `duration_s * sample_rate_hz`。 |
| `sample_rate_hz` | 接收采样率，单位 Hz | 影响观测几何样本数、回波样本数和反演频谱。 |

采样点为 `np.arange(N) / sample_rate_hz`，最后一个样本通常是 `(N-1)/sample_rate_hz`，不严格等于 `duration_s`。

连续波使用 `receive`；chirp 脉冲序列使用 `schedule` + `radar_system` + `receiver_sampling`。二者不能同时出现。GUI 切换波形时会改写当前会话的事件源，载入已包含历史字段的 JSON 会直接报错。

Chirp 下，`target.extent_path_m`（界面标签「采集路径窗」）显示在「接收采样」卡片中。它是相对质心参考回波、两侧各允许的最大额外双程路径，单位可选 m 或 km。未知尺度和余量都写在这一个数里。同一卡片用只读文字给出静止时标的门时延、前沿取整后的样点数 $n_{\mathrm{pre}}$、整行样点数，以及由 Chirp 带宽算出的压缩后距离分辨 $c/(2B)$。$n_{\mathrm{pre}}$ 写在门时延后面的括号里，比门时延对应的物理样点数最多多 1。连续波不显示该控件。JSON 键仍写在 `observation.target` 下。发射时序里的脉冲宽度保存为秒，界面下拉项从上到下依次是 s、ms、µs；载频、带宽和快时间采样率已经可以选 SI 词头。高分辨试例里的 $40\,\mu\mathrm{s}$ 脉宽会显示成 40 µs，而不是 0.00004 s。

### 6.4 观测产物

观测解算把接收时间轴、发射/散射时刻、收发视线和距离保存到
`runs/<实验名>/observation_info.npz`。该文件由 pipeline / GUI 自动注入 echo 配置，不需要在顶层 JSON 里手写路径。

### 6.5 `ephemeris`

仅当使用 `horizons_vectors` 或 `astropy_geodetic` 等真实星历/测站模式时才重要。

| 字段 | 含义 | 建议 |
| --- | --- | --- |
| `query_step_s` | Horizons 状态表间隔 | 越小插值误差越小，查询越多。短时窗口可从 60-300 s 开始。 |

参考中心、参考平面、星历 padding、HTTP 分块/重试/缓存以及光行时求解器迭代策略均由算法内部管理，不再显示或保存为实验字段。

## 8. 周期反演参数

`inversion` 读取 `echo.npz`，对复基带 I/Q 做频谱分析和周期搜索。

| 字段 | 含义 | 建议 |
| --- | --- | --- |
| `stft_window_samples` | STFT 窗长 | 决定时间/频率分辨率；必须小于或等于样本数。 |
| `stft_overlap_fraction` | STFT 重叠比例 | 常用 0.5-0.75。 |
| `period_min_s` | 搜索最小周期 | 应覆盖预期周期下界。 |
| `period_max_s` | 搜索最大周期 | 应覆盖预期周期上界；不要盲目设太宽。 |
| `period_grid_size` | 周期网格密度 | 越大越慢，峰值定位越细。 |

连续波反演流程是：可选平动多普勒补偿、STFT、提取总功率/频谱质心/RMS 带宽三类特征、对特征序列做 Lomb-Scargle 周期搜索。只有当配置或 echo 元数据中包含 `translation_coefficients_hz` 时，才会执行多项式平动多普勒补偿。

Chirp 反演先判断相干分组里的有效连续脉冲数是否够组成 CPI；够长时按原窗口和步长逐 CPI 计算匹配滤波、对齐、慢时间 FFT，并立即提取五项特征，进度显示已完成 CPI 数，不再保留整场相关数组和完整谱立方体。分组太短、CPI 无法形成时，分块提取所有脉冲的总能量、距离质心和距离展宽。两分支都保留全部科学观测、原时刻与原权重，完整特征存入 `period_observables.npz`；`dynamic_spectrum.png` 仅展示采样诊断，CPI 图最多保留 128 帧，距离列按展示内存预算选取，完整 Doppler 轴保留。大数组采用磁盘映射；单CPI仍需要工作区，超过512 MiB估算预算时明确拒绝，预算不等于进程峰值。科学预处理特征与完整网格CPI显示产物保存在回波目录的processing_cache，相关参数或源文件身份改变时失效；估计器切换仅使特征失效，共同FFT谱可复用。统一结果卡片的「实际反演特征」读取上述科学观测；「逐脉冲检查」为独立全场检查。

<a id="optional-period-methods"></a>

### 8.1 独立选择 Chirp 周期反演功能

「可选反演功能」中的视线相位补偿、多谐波特征拟合、周期局部细化可以独立选择；它们不是精度依次提高的等级。取消这三项可得到单谐波、无经度补偿、仅网格搜索的基础模式，共同截距、正确时标和原始特征样本仍保留。功能只接入 Chirp；CW 页面隐藏并裁剪这些字段，直接向 CW 配置传入它们会报错。

| 配置字段 | 界面操作与缺省行为 |
| --- | --- |
| `period_selection` | 默认 `predictive_joint` 使用整 Run 留出预测融合；`legacy_consensus` 保留旧候选投票作为对照 |
| `los_phase_compensation` | 「视线相位补偿」，默认 `false` |
| `spin_axis_ra_deg` / `spin_axis_dec_deg` | 独立填写 ICRS 自转轴赤经 0–360°、赤纬 −90–90°；补偿或组合比较时必填，不从 `echo.target` 自动复制 |
| `phase_period_convention` | `half_rotation` 使用两倍经度补偿，`full_rotation` 使用一倍；默认 `half_rotation`，程序不按形状自动选择 |
| `multi_harmonic_enabled` | 「多谐波特征拟合」；缺省沿用旧 `harmonics` 并据其恢复界面，明确关闭时有效谐波数为 1 |
| `harmonics` | 正整数；旧配置未给时为 1，明确开启多谐波而未给时为 2；开启多谐波或组合比较时至少为 2 |
| `refine_period` | 「周期局部细化」；默认 `true`，旧配置省略时继续开启 |
| `compare_methods` | 「比较全部功能组合」，默认 `false`；额外比较八组合，不替换当前主结果 |

布尔值必须写 JSON 的 `true` / `false`，不能写成字符串。关闭多谐波后隐藏的谐波数不参与计算；关闭相位补偿且不比较时，隐藏极轴也不参与计算。功能不读取初始相位或形状模型。补偿使用散射时标，只允许 `period_time_role=scatter_centroid`；模型、几何条件及不能消除的偏差见[算法说明](INVERSION_ALGORITHM.md#optional-method-contract)。

多谐波拟合的是总能量、距离质心等随时间变化的特征，不改变发射 Chirp 或匹配滤波；拟合更好不表示周期更准确。局部细化只减少网格离散误差，不能消除波形／几何模型偏差。旧 CLI 省略 `refine_period` 与 GUI 保存后的显式开关在边界候选规则上存在兼容差异，见[候选策略](INVERSION_ALGORITHM.md#candidate-policy)。

展开或收起功能时保留焦点、滚动位置和已达到的滚动范围，切换阶段或载入配置后重新计算。保存保留有效隐藏参数，重新开启时可继续编辑；收起后不再使用的非法数值草稿会被舍弃，原有效配置值保留，不会因无效隐藏草稿阻止关闭功能。

<a id="method-comparison-output"></a>

### 8.2 比较八种组合并读取结果

「比较全部功能组合」对同一份已提取特征、时刻、权重和周期范围计算相位补偿开／关 × 单谐波／所选多谐波 × 局部细化开／关共八组合。比较包含补偿和多谐波，因此即使主结果未启用两者，仍须输入极轴和至少为 2 的谐波数。它不会按真值或最大分数自动切换主算法。

`summary.json` 与 `best_summary.json` 保持主结果入口。实际选项记录在 `search_diagnostics.method_options`，几何来源和周期约定记录在 `phase_geometry`，各特征诊断记录有效谐波数、细化与补偿状态。`period_selection.json/html` 记录主结果融合候选、通道评分、排除／去重原因、验证模式、边界与远峰歧义；不能把单特征误差条套到最终融合周期。

比较报告为 `method_comparison.html` 和 `method_comparison.json`，GUI 完成日志提供路径。报告列出各特征的周期、拟合分数与状态；读取报告不会启动计算。关闭比较后，同名报告更新为「本次未开启」，避免误读上次结果。Chirp 拟合分数没有校准的假警报概率，显著性仍显示「未评估」。

```powershell
conda activate pytorch
python pyside_gui.py
# 直接运行时，在反演配置中填写上述独立字段
python inversion/scripts/estimate_period.py --echo runs/实验名/echo/echo.npz --config 我的反演配置.json --output runs/实验名/inversion
```

## 10. 蒙特卡洛仿真方案

当前 GUI 适合单次实验的交互配置、执行和检查。蒙特卡洛仿真更适合使用命令行批处理：先准备一组 pipeline JSON 文件，每个文件对应一个样本工况，例如不同 SNR、自转周期、初始相位、散射斑位置、形状模型或观测几何。

推荐工作流如下：

1. 用 GUI 调通一个基准配置，并另存为 `configs/mc/base.json`。
2. 用脚本批量生成 `configs/mc/case_0001.json`、`case_0002.json` 等配置文件。每个配置文件只修改需要随机化的参数，并记录随机种子。
3. 对每个 JSON 调用流水线命令：

```powershell
conda activate pytorch
python pipeline.py --config configs\mc\case_0001.json --run-name mc_case_0001
```

4. 每个样本的输出会进入独立目录，例如 `runs/mc_case_0001/`。后续统计脚本读取各目录下的 `inversion/best_summary.json`、`inversion/summary.json` 和 `echo/summary.json`。
5. 统计阶段建议汇总：真值周期、反演周期、相对误差、是否落入容差、SNR、观测时长、波形类型、是否启用强散射点、随机种子。

如果样本很多，可以把第 3 步改成批处理脚本或任务队列。建议先串行跑 3-5 个样本确认输出字段稳定，再并行运行大批量实验。并行时要保证每个 case 的 `run-name` 唯一，避免多个进程写入同一目录。

GUI 和蒙特卡洛并不冲突：GUI 用来设计、检查和解释单个 case，命令行批处理用来做规模化统计。后续如果要实现正式蒙特卡洛模块，比较合适的形态是新增 `monte_carlo.py`：读取一个样本清单或生成规则，批量调用现有 pipeline，最后输出 CSV/Excel 汇总和误差分布图。

## 11. 参数配置注意事项

1. 先用短时长、低采样率和较小周期网格跑通，再逐步增加规模。
2. 不要让 `stft_window_samples` 大于回波样本数。
3. 真实目标使用 `horizons_vectors` 时，先检查 `ephemeris.query_step_s` 的敏感性。
4. 真实地面站优先使用 `astropy_geodetic`，并保持参考平面一致。
5. 载频越高，相同几何误差对应的相位误差越敏感，应相应检查星历、测站和光行时精度。
6. 示例中的 `scattering_spot` 会让周期特征更清晰；真实散射模型可能不会这么理想。
7. `snr_db` 越高，周期图越干净。评估鲁棒性时应降低 SNR 或加入更真实的系统误差。
8. 如果运行时间过长，先区分计算规模和显存问题：降低 Run 数量、Run 时长、PRF、连续波采样率或反演网格会直接减少计算量；只有显存不足时才调小回波 chunk。对 Chirp 小网格，过小的 `facet_chunk_size` 反而会因大量 GPU 小调用而变慢。
9. 如果要复现实验，保存顶层 pipeline JSON，并保留 `runs/<实验名>/configs/*.generated.json`。

## 12. 关于光行时加速与精度

早期实现按接收采样点逐个求解三事件光行时。每个采样点都要在 Python 层调用多次 `retarded_time()`、状态查询、范数计算和单位向量计算。样本数一大，主要耗时来自 Python 循环和重复函数调用，而不是光行时固定点迭代本身。

当前实现把整条接收时间轴作为数组批量处理：

1. 一次性批量求接收时刻对应的散射时刻。
2. 一次性批量求散射时刻对应的发射时刻。
3. 一次性批量计算目标、发射站、接收站位置。
4. 一次性批量计算距离和视线单位向量。

这仍然是同一个固定点方程、同一个 `tolerance_s`、同一个 `max_iter`，只是把逐点 Python 循环换成 NumPy 向量化数组运算。对 `static`、`linear`、`horizons_vectors` 插值状态和 `astropy_geodetic` 批量状态，数学结果应与逐点算法一致。开发验证中，线性/静态小样本与旧逐点算法逐项对比最大差异为 0。

为什么能快很多：以前每个样本都单独进入 Python 循环；现在每轮迭代用底层 C/NumPy 对整批样本计算，函数调用次数从“样本数 × 迭代次数”量级降为“迭代次数”量级。半小时到一分钟以内的提升在这种瓶颈结构下是合理的。

需要注意的边界：

- 向量化不是降低精度，也不是减少迭代阈值。
- 如果状态模型内部本身是低精度插值，最终精度仍受 `query_step_s` 和星历源限制。
- 如果真实实验要求更严，应对 `tolerance_s`、`query_step_s`、`sample_rate_hz` 做敏感性检查。
- 当前解的是小行星质心三事件几何；每个面元的精细路径在回波模块中近似处理，不等同于逐面元精确光行时解。

## 13. 常见问题

### 13.1 交互图在哪里打开

当前 GUI 固定通过系统浏览器打开 Plotly 交互图。若浏览器未自动弹出，可在 `.gui_state/previews/` 中打开对应的回波预览 HTML 文件。

### 13.2 点击中止后为什么输出目录还存在

中止只停止计算进程，不删除已生成的配置快照、输出或部分结果，以便保留现场。日志会记一条 `已中止：<阶段>`（警告级），阶段状态显示“已中止”，不会再报成失败、也不弹错误对话框；随后可重新点击 `运行当前阶段` 从头执行该阶段，或点击 `运行完整 pipeline` 重跑全部阶段。

### 13.3 为什么示例周期图只有真值附近一个明显峰

示例配置是干净、短链路、已知真值的仿真实验，且强散射斑会增强周期可辨识性；这不代表真实数据一定同样理想。真实雷达数据通常还需要下变频、匹配滤波或距离门、标定、平动补偿、异常点处理和误差建模。

### 13.4 能直接拿真实回波进反演吗

不能把未经处理的真实原始雷达数据直接等同于当前 `echo.npz`。当前反演输入假设已经是统一时间轴上的复基带 I/Q，并且具备必要元数据。真实数据需要先转换成与 `echo.npz` 兼容的数据格式，并完成相应预处理。

已经用本流水线生成过 `echo.npz` 时，可以跳过观测与回波：把 `实验名` 与 `输出目录` 指回那次 run，选择 `周期反演` 后点 `运行当前阶段`，日志会显示 `复用已有回波数据：…\echo\echo.npz`。反演设置取自当前 GUI 参数，因此重跑前请确认搜索范围（`period_min_s`/`period_max_s`）、`cpi_duration_s` 与该回波的采样参数、真值周期相匹配；当前回波有效配置与产物来源不一致时会阻断，而不是只给警告。

### 13.5 星历覆盖不足会怎样

如果内部星历安全余量仍不足以覆盖发射或散射时刻，程序会明确报出插值越界并停止，不会继续给出不可靠结果。此时应检查目标距离、观测窗口和时间原点；安全余量不再由 GUI 字段手工调节。

### 13.6 chirp 预览里的脉冲压缩二维图怎么读

第一幅是脉冲保存行的原始 `|iq|`：横轴是脉冲保存行内时间，纵轴是脉冲序号。点目标试例的带宽是 $1\,\mathrm{kHz}$，距离分辨约 $150\,\mathrm{km}$，快时间上看到的是发射包络本身。网格试例把带宽设为 $150\,\mathrm{MHz}$，距离分辨约 $1\,\mathrm{m}$，和百米级形体同量级；压缩后可以出现距离方向的结构，光滑凸体上更常见的是亮斑和展宽，而不是把直径均匀切成几十个一样亮的距离单元。

第二幅是同一批脉冲做匹配滤波后的二维距离像 `|MF|`：峰值抬高到约 $N$ 倍（$N$ 为脉冲占用的样点数），快时间方向由矩形变成主瓣宽度约 $1/B$ 的 sinc 形，旁瓣比主瓣低十几 dB，并延伸到整个保存行。第三幅是沿脉冲平均的一维距离像，橙色虚线是预计质心回波位置。三幅图的纵向包络都由目标姿态随自转的变化决定。

### 13.7 为什么关掉强散射斑后快时间幅度包络的周期可能只有真值的一半

`models/ellipsoid.obj` 由二十面体细分得到，顶点集合在绕自转轴旋转 180° 后与自身完全重合。当自转轴就是该对称轴、收发几何固定时，相隔半个自转周期的两个时刻照明到的面元集合、面元权重和面元相对路径完全相同，回波整体重复出现。此时从回波包络量到的周期是 `target.rotation_period_s` 的一半。`scattering_spot` 的作用正是打破这种几何对称性，使自转周期在回波中可辨识；做周期可辨识性实验时不要把它关掉。

图像HTML按浏览器可见页面大小自适应，单图或多图均使用完整可见高度；历史HTML打开时仅升级布局，不重跑计算。本机缓存只核对路径、大小、修改时间与处理参数，不使用SHA256。GUI新生成页面共享本地Plotly脚本，复制单个GUI HTML到其他目录时还需保留相对脚本路径；CLI默认生成可独立携带的HTML。未压缩回波不再生成完整提取副本，阶段重复对象按引用保存，两种估计器共用同一FFT显示谱。默认CPI显示文件不能作为双精度科学功率谱导出；需要后者时，使用反演CLI的`--export-full-cpi-power`。已有周期精度问题仍见信号形成诊断，存储调整不构成CPI改善精度的证据。

### 13.8 多普勒估计策略怎样选择

周期反演参数中的“多普勒特征计算方法”默认“FFT功率谱法（默认）”，可显式选择“相关法（实验性）”。旧界面分别称“谱功率矩”和“低频有效估计”；本次只改显示名，JSON仍为 `spectral_moments`／`narrowband_lag`，保存的选择和计算结果不变。相关法要求至少12脉冲和高相干窄频模型，失败窗口的两个多普勒特征不参加搜索，其他三特征和FFT图不变；它不是任意频谱的RMS测量工具。当前无噪声椭球作业在CPI=1秒、步长=0.25秒时，相关法宽度主峰约5398.02秒、质心主峰仍约5427.72秒，没有证明最终周期普遍更准。收益、负结果及横条纹分析见[配对实验](https://github.com/lewgeon/radar-asteroid-rotation-period-pipeline/blob/chirp-pulse/docs/4.3/vs_4.2/experiments/reports/2026-10-09_SIGNAL_FORMATION_AND_INTEGRATION_COST.md#cpi-coherence-20261014)。

代码更新后重启GUI，使新选项和对齐算法生效。旧标量特征缓存按v4重新计算，兼容的已有CPI显示谱仍可复用；已保存的历史反演结果仍可查看，但不会因打开HTML自动变成新算法结果，需要运行周期反演才能获得新结果。改变估计器会改变实际反演和对应中间结果使用的策略，不形成另一条独立反演流水线。

### 13.9 Run分隔线与距离—多普勒看图耗时

全场原始回波/脉压HTML左上方，在“信号范围”“完整记录范围”同一按钮组提供“显示/隐藏Run分隔线”：首次点击隐藏，再点恢复，只改变灰色Run边界的可见性，不改变数据、坐标、当前缩放或其他标记；中途使用范围按钮不会破坏下一次显示／隐藏。单Run没有边界时不显示此按钮。通过GUI打开旧全场HTML时，会把右侧旧开关合并到左侧按钮组，不重算；已打开的浏览器页面需刷新。显示选择仅在当前页面内有效，重新打开默认显示分隔线。

距离—多普勒只读取已完成反演保存的选定CPI，不在看图时脉压、FFT或反演。当前GUI参数不参与历史结果绘图，卡片显示保存的处理路径、观测数与估计器；修改参数后要运行周期反演才获得新结果。原始回波在文件存在时可查看，其余按钮按完成状态和对应保存数据置灰。旧版已认证HTML仍可直接打开；旧反演缺少逐脉冲／脉压检查或指定CPI频谱时，通过运行周期反演补齐。首次保存检查数据会增加反演执行时间，不能声称这一步没有额外计算。规则与验收见[单执行入口专题](https://github.com/lewgeon/radar-asteroid-rotation-period-pipeline/blob/chirp-pulse/docs/4.3/vs_4.2/changes/NATIVE_RANGE_FEATURES.md#single-execution-20261014)，已有CPI单帧构图性能范围见[图像读取专题](https://github.com/lewgeon/radar-asteroid-rotation-period-pipeline/blob/chirp-pulse/docs/4.3/vs_4.2/changes/NATIVE_RANGE_FEATURES.md#run-view-20261014)。

### 13.10 反演计算设备与误差诊断

“图像结果→融合诊断”只读打开已保存的`period_selection.html`，原始数据为`period_selection.json`；缺报告时按钮置灰，不从查看启动计算。报告列出规则、有效Run、留出／回退模式、各候选及通道评分、排除／去重原因、边界和远峰诊断；分数不是置信概率，不自动给最终3σ。GUI按标准`runs/<实验名>/inversion/`查找结果；独立升级目录的报告需直接打开。

“周期融合方法”默认“留出预测融合（默认）”，JSON为`period_selection="predictive_joint"`；可选`legacy_consensus`旧投票供对照。默认规则保留各单特征结果，在共同候选周期上比较整Run五折预测，以通道评分中位数选周期；少于10个有效Run明确回退共同拟合评分，不称为留出验证。有效掩码完全相同的仿射副本去重，一般通道相关性和污染多数仍可能影响结果。H1保持默认，不按已知周期自动选阶数或删除多普勒。CW隐藏并裁剪此字段，保存重载恢复Chirp实际选择。

重启GUI后，在Chirp周期反演阶段的“反演计算设备”选择“CPU（默认）”或“GPU（CUDA:0）”，JSON分别为`cpu`／`cuda:0`。GPU使用PyTorch CUDA进行匹配滤波、Fourier距离对齐、慢时间FFT及周期网格搜索，不改变CPI长度、窗、特征定义或选峰规则；八组合比较和Run重采样也加速网格。标量特征归约、相关法拟合、周期局部细化和病态网格仍由CPU执行。无可用CUDA时日志明确提示回退CPU；显存不足则报错，不静默改精度。科学缓存按实际设备隔离，不承诺逐位相同或所有输入都有相同加速比；CW原搜索仍用CPU。算法和诊断字段见[GPU周期搜索](INVERSION_ALGORITHM.md#gpu-period-search)。

“周期误差评估”默认关闭，可选“按Run重采样（实验性）”；启用后显示次数（默认200、至少30）和随机种子（默认20261015）。程序先按原设置完成反演，再将同一Run的全部CPI及所有特征一起抽样，每次重做全范围周期搜索和当前配置的融合选择；不会重算整份IQ。至少需要10个正权且存在有效特征的Run；预测融合重抽后若正权唯一Run少于10而切换评分模式，则计失败，不混入分位数。全部抽样不可用时不产生区间并说明原因；Run不足时保存“不可用”原因，仍保留反演结果。Run有共同系统误差、观测变化不能交换或波形模型错误时，重采样不能覆盖这些偏差。

完成后从“图像结果→误差诊断”打开保存报告；未启用或尚未完成时按钮置灰，看图不触发计算。报告区分各特征的局部σ／条件性±3σ和重采样共识周期的经验分位数；最终总误差3σ仍不提供。重采样会增加重复搜索成本，选择GPU现在可加速其中网格计算，局部细化及共同预测融合仍在CPU。报告同时保存为反演输出目录的`period_uncertainty.json`与`period_uncertainty.html`。当前观测与控制实验的覆盖率边界见[误差评估实验](https://github.com/lewgeon/radar-asteroid-rotation-period-pipeline/blob/chirp-pulse/docs/4.3/vs_4.2/experiments/reports/2026-10-14_PERIOD_UNCERTAINTY_AND_FUSION.md#uncertainty-controls-20261015)。
