# ADC 采样规划职责迁移计划

> 状态：尚未实施，随 4.2 完成迁入 4.3。当前代码仍在 `observation/src/planning.py` 中生成 ADC 整数网格和二维保存行；只有完成本文验收标准后才能记为已实现。2026-09-23 起 Chirp 不再有 `pre_guard_s` / `post_guard_s`，保存行余量只来自 `target.extent_path_m`；本文里把这两个时间字段当作现行输入的句子已经过时。

## 1. 计划目的

当前观测解算阶段同时完成三事件几何求解和离散 ADC 布局规划，因此会在尚未生成回波时计算 `row_start_sample`、`row_valid` 和 `window_overlap`，并输出“保存窗/ADC 整数索引重叠”等与二维回波存储格式有关的警告。本计划拟将依赖采样率、整数网格和二维保存格式的计算迁移到回波仿真阶段，使观测解算输出连续时间几何，回波仿真负责把连续事件映射到离散采样网格。

本计划不改变发射 Run 的自动选取原则，不改变三事件光行时方程，不改变当前回波在唯一全局 ADC 索引上叠加后再映射为二维视图的计算方式，也不以半开区间作为解决一般行重叠或物理回波重叠的手段。

## 2. 当前实现

当前数据流如下：

```text
observation
  自动选取 Run
  生成脉冲发射时刻
  求解发射—散射—接收三事件几何
  根据采样率建立 Run 级 ADC 整数网格
  计算每脉冲二维保存行
  检查物理回波重叠和保存行重叠
  写入 observation_info.npz
            ↓
echo
  读取已经规划好的 ADC 网格
  对每个 Run 构造唯一全局 ADC 索引
  在唯一采样时刻上叠加所有脉冲贡献
  映射为二维 [pulse, fast_time] 数据
  写入 echo.npz
            ↓
inversion
  读取 echo.npz
```

`observation/src/planning.py::plan_reception()` 当前读取 `fast_sample_rate_hz`、`pre_guard_s`、`post_guard_s`、脉冲宽度、目标路径展宽和路径变化率，并生成 `rx_adc_start_elapsed_s`、`rx_adc_stop_elapsed_s`、`row_start_sample`、`row_fast_time_offset_s`、`centroid_fractional_offset_s`、`row_valid`、`fast_sample_count`、`signal_echo_overlap` 和 `window_overlap`。这些字段随后写入 `observation_info.npz`，由 `echo/src/geometry.py` 读取。

`echo/src/echo.py` 并非逐行独立生成信号。它先用 `np.unique(global_q)` 得到每个 Run 的唯一 ADC 整数索引，在这些物理采样时刻上累加全部脉冲贡献，再把结果映射回二维保存行。当前需要调整的是 ADC 布局的生成阶段和数据契约，不是回波叠加算法。

## 3. 目标职责边界

### 3.1 观测解算负责连续时间几何

观测解算保留以下职责：

- 扫描几何可见性并自动选取发射 Run。
- 按 PRF 生成能够完整落入 Run 调度区间的脉冲发射前沿时刻。
- 求解每个脉冲的发射、散射和质心参考回波到达时刻。
- 输出发射与接收视线、上下行距离、公共路径变化率和散射时标导数。
- 输出 Run、track 和 coherence 标识。
- 使用连续时间的保守调度预留长度 $H$ 约束自动选时。

观测解算不再建立 ADC 整数索引，不再生成二维保存行，不再判断 `window_overlap`，也不再输出只对离散回波布局有意义的警告。

### 3.2 回波仿真负责离散采样与数据布局

回波仿真新增以下职责：

- 读取观测解算输出的连续时间三事件几何。
- 使用 ADC 采样率、保护时间、脉冲宽度、目标路径展宽和时标伸缩计算每脉冲连续回波覆盖范围。
- 检查单站最后一次发射、收发切换和最早回波之间的精确可行性。
- 为每个 Run 建立连续 ADC 窗并对齐到整数采样网格。
- 计算每个脉冲的行起始索引、快时间偏移、亚采样偏移和有效掩码。
- 区分并报告物理回波重叠与二维保存行重叠。
- 继续在唯一全局 ADC 索引上叠加所有脉冲贡献，然后映射为二维输出。
- 在生成信号前完成内存估算和输出规模限制检查。

### 3.3 反演阶段保持现有输入契约

反演阶段继续读取 `echo.npz`，不直接读取 `observation_info.npz`。ADC 布局字段由回波阶段写入 `echo.npz` 后，反演数据类仍可按当前字段名读取，因此本次职责迁移不要求同时重写反演算法。

## 4. 字段迁移

### 4.1 保留在 `observation_info.npz`

| 字段 | 原因 |
| --- | --- |
| `start_utc` | 所有相对时间的 UTC 参考。 |
| `emit_elapsed_s` | 发射事件的独立时间轴。 |
| `scatter_elapsed_s` | 目标质心散射事件。 |
| `elapsed_s` | 质心参考回波到达时刻，当前字段名暂时保留以避免扩大迁移范围。 |
| `tx_los_icrs`、`rx_los_icrs` | 回波几何。 |
| `tx_range_m`、`rx_range_m` | 公共传播路径。 |
| `common_path_rate_m_s` | 脉内时标与相位变化。 |
| `scatter_receive_rate` | 接收样点映射到散射时刻的局部导数。 |
| `run_id`、`track_id`、`coherence_id` | 事件分组。 |
| `resolved_runs`、可见窗口等元数据 | 记录选时结果与来源。 |

### 4.2 从 `observation_info.npz` 移至 `echo.npz`

| 字段 | 迁移原因 |
| --- | --- |
| `rx_adc_start_elapsed_s` | 依赖采样与接收保护策略。 |
| `rx_adc_stop_elapsed_s` | 依赖 ADC 网格向上取整。 |
| `row_start_sample` | 纯整数采样布局。 |
| `row_fast_time_offset_s` | 由 ADC 网格和行起点共同决定。 |
| `centroid_fractional_offset_s` | 由参考回波与整数网格对齐产生。 |
| `row_valid`、`valid_plan` | 二维行相对 Run 级 ADC 窗的有效掩码。 |
| `window_overlap` | 二维保存视图属性。 |
| `fast_sample_count` | 由采样率和每脉冲保存范围决定。 |
| `estimated_window_iq_bytes`、`estimated_continuous_iq_bytes` | 回波输出规模属性。 |

`signal_echo_overlap` 可以直接迁移到回波阶段。它是连续时间上的物理属性，不依赖整数 ADC 对齐，但主要决定回波叠加与下游解释；与 `window_overlap` 在同一阶段统一计算和报告可以减少概念混淆。

## 5. 配置所有权

第一步采用最小迁移：暂时保留用户 JSON 中现有的 `observation.receiver_sampling` 路径，pipeline 在生成 `echo.generated.json` 时把该配置复制到回波阶段。观测解算只读取自动选时所需的连续时间保护参数，不读取 `fast_sample_rate_hz`；回波仿真读取完整采样配置并完成网格规划。这样可以先调整运行职责而不同时破坏 GUI 和用户配置。

完成职责迁移后再评估是否进行第二次 schema 调整：将 `fast_sample_rate_hz` 明确归入 `echo.receiver_sampling`，并把“Run 级采集首尾保护”与“每脉冲保存行余量”拆成不同字段。第二次调整不应和首次代码迁移混在同一个提交中，否则难以判断行为变化来自模块迁移还是配置语义变化。

自动选时的调度预留长度 $H$ 暂时继续使用 `post_guard_s`、脉冲宽度和目标路径展宽计算连续时间保守上界。该计算不使用 ADC 采样率和整数索引，因此可以保留在观测阶段。后续应单独审查这个保守公式是否过度累加了可以并行发生的传播与切换过程，但不将该问题混入本次职责迁移。

## 6. 建议的数据接口

在 `echo/src` 中新增独立的采样规划模块，例如 `sampling_plan.py`，定义 `AdcSamplingPlan`。该模块只接收连续几何、波形参数、接收采样参数和雷达工作模式，返回离散布局，不依赖散射模型或噪声模型。

建议接口如下：

```python
def build_adc_sampling_plan(
    geometry,
    waveform,
    receiver_sampling,
    radar_system,
    *,
    target_extent_path_m,
) -> AdcSamplingPlan:
    ...
```

`AdcSamplingPlan` 保留现有 `ReceptionPlan` 中的 ADC 布局字段。`echo.py` 先调用该接口，再运行点目标或面元散射内核。这样 ADC 规划可以独立测试，也避免把逻辑重新堆入 `echo.py`。

观测解算输出格式应增加明确的元数据，例如 `data_layout="pulse_event_geometry"`，表示文件只包含逐脉冲连续事件，不承诺 ADC 布局。回波输出继续使用 `data_layout="pulse_adc_windows"`。

## 7. 实施步骤

### 阶段一：建立行为基线

1. 为 `configs/chirp_test.json` 固定连续几何、ADC 窗、行索引和重叠标志的基准结果。
2. 增加三类测试：仅公共边界保存行重叠、保存行大范围重叠但物理回波不重叠、物理回波真实重叠。
3. 验证当前生成器在共享全局 ADC 索引处产生完全相同的信号和噪声值。
4. 检查反演阶段是否把二维视图中的公共 ADC 样点重复计权，并记录结论；如存在，应另立修复项，不在职责迁移中静默改变反演统计。

### 阶段二：提取 ADC 规划模块

1. 将 `plan_reception()` 中从连续事件到 ADC 布局的逻辑迁移到 `echo/src/sampling_plan.py`。
2. 保持所有取整公式、数组形状和字段值不变，先实现逐项等价迁移。
3. 让 `echo.py` 在加载连续几何后调用新模块。
4. 对同一配置比较迁移前后的 `rx_adc_start_elapsed_s`、`rx_adc_stop_elapsed_s`、行索引、掩码、重叠标志、`clean_iq` 和加噪 `iq`，要求完全一致或仅存在事先定义的浮点容差。

### 阶段三：缩减观测输出

1. 从 `ObservationInfo` 和 `observation_info.npz` 中移除 ADC 布局字段。
2. 删除观测阶段的保存行重叠警告、ADC 内存估算和整数网格进度信息。
3. 保留自动选时所需的连续时间调度预留计算。
4. 更新 `echo/src/geometry.py`，使其接受新的几何专用观测文件。
5. 由回波阶段在生成信号前输出 ADC 布局与重叠信息。

### 阶段四：兼容旧观测文件

1. 回波模块读取旧版 `observation_info.npz` 时识别其中已有的 ADC 字段。
2. 过渡期内优先重新规划 ADC 布局，并在测试中比较旧布局与新布局；不一致时给出包含字段名的明确错误，避免静默改变采样时刻。
3. 为旧文件提供一个明确的兼容期限或离线转换脚本，避免长期维护两套权威布局。
4. 新文件不再写入已迁移字段，防止出现“观测文件布局”和“回波阶段重新规划布局”两个互相冲突的事实来源。

### 阶段五：更新 pipeline、GUI 和文档

1. pipeline 在生成回波配置时传递采样规划所需参数，并把采样率与 Chirp 带宽校验保留在回波阶段。
2. GUI 字段位置可以暂时保持不变，但阶段校验和日志归属必须跟随新职责。
3. 观测阶段日志只报告选时、脉冲事件和光行时几何；回波阶段日志报告 ADC 网格、内存规模、保存行重叠和物理回波重叠。
4. 更新 observation 与 echo 的 README、架构文档、字段词汇表和观测选时文档。

## 8. 警告策略

建议把重叠信息分为两类：

- `window_overlap=true` 且 `signal_echo_overlap=false`：二维保存行共享全局 ADC 样点，但物理回波未重叠。当前生成器能够正确处理，应显示为普通信息或数据布局说明。
- `signal_echo_overlap=true`：同一物理 ADC 时刻包含多个脉冲回波。当前生成器会进行复数叠加，但下游算法可能需要显式支持，应显示为警告并记录到回波元数据。

“旧版逐行回波生成器必须拒绝该计划”不应在默认现代流水线中作为用户警告出现。若仓库仍保留旧消费者，应由兼容性检查针对实际选中的消费者报告；若旧消费者已不存在，应删除这条用户级提示，只在迁移文档中保留历史说明。

## 9. 验收标准

重构完成后应满足：

1. 单独运行观测解算时，不需要 `fast_sample_rate_hz`，也不产生任何整数 ADC 索引或二维保存行警告。
2. `observation_info.npz` 包含完整逐脉冲三事件几何，足以让回波阶段重新建立采样计划。
3. 回波阶段在生成任何信号前完成单站切换可行性、ADC 网格、内存和重叠检查。
4. 对现有有效配置，迁移前后的发射、散射、接收时刻以及最终复数回波保持一致。
5. 当前 `chirp_test.json` 的保存行边界重叠信息出现在回波阶段，并明确显示“物理回波未重叠”。
6. 对真实物理回波重叠案例，同一全局 ADC 样点等于所有相关脉冲复数贡献之和。
7. 同一全局 ADC 样点映射到多个二维行时，信号值和噪声值完全相同。
8. 反演阶段对重叠二维视图的处理方式有测试和文档说明，不会在不知情的情况下重复计权。
9. CW 路径不受 Chirp ADC 布局迁移影响。
10. observation、echo、inversion 和 GUI 的相关测试全部通过。

## 10. 主要风险

- 自动选时仍使用保护参数估算 $H$，而精确 ADC 布局在后续阶段生成；两者必须使用一致的脉冲宽度、目标展宽和保护定义，否则可能出现粗规划允许、精确规划拒绝的情况。
- `elapsed_s` 在 Chirp 观测文件中实际表示质心参考回波时刻，名称不够明确。此次可暂时保留，但接口元数据必须说明含义，后续可单独迁移为 `receive_elapsed_s`。
- 旧观测文件和新观测文件的识别不能依靠字段缺失后盲目填零，应使用明确格式标识。
- 将采样率从观测配置移动到回波配置会影响 GUI、pipeline 和历史 JSON，不应与核心职责迁移一次完成。
- 当前最终回波仍保存为二维重叠视图。职责迁移不会自动解决下游重复计权问题，也不会把唯一 Run 级 ADC 序列变成新的正式输出格式。
- 物理回波重叠是实验波形和传播条件共同造成的真实现象，不能通过裁剪二维行或采用半开区间消除。

## 11. 建议审查的问题

请审查者重点判断：

1. `observation_info.npz` 是否应彻底去除 ADC 布局，还是应保留连续时间的预计接收范围用于独立检查。
2. 单站精确收发冲突检查放在回波阶段是否可以接受，还是需要在观测阶段保留一个不依赖整数网格的连续时间检查。
3. `signal_echo_overlap` 应归属观测几何还是回波采样模块。
4. 第一阶段是否应保持当前二维输出不变，还是同步增加唯一 Run 级一维 ADC 数据作为权威输出。
5. 反演模块是否会对二维重叠视图中的公共样点重复计权；若会，应该使用全局索引去重、调整统计权重，还是改为直接消费一维 Run 数据。
6. 旧版观测文件应通过兼容读取、转换脚本还是明确停止支持。
7. `pre_guard_s`、`post_guard_s` 是否应继续同时控制 Run 级 ADC 外边界和每脉冲保存行余量，还是应在后续 schema 中拆分。
