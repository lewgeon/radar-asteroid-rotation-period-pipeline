## 2. 第一轮复核：核实的 6 类问题

### 2.1 窗尾保证原先**不成立**（最实质）

**复核主张**：`n_after = ceil((post_guard + max(after))·fs)` 只做向上取整时，末格时刻可能早于"最晚回波尾沿 + `post_guard`"。

**我的核实**：用真实 `plan_reception` 扫 576 组参数，**最坏 −0.4634 个采样**，参数 `fs=1000, pre=0, post=0, prf=20.5`——与复核给的数字完全一致。

**我上一轮为何没发现**（关键）：守护测试 `test_reception_window_covers_echo_and_post_guard` 的 6 组参数里 `post_guard·fs` 全是整数，实测缺口恒为 `+0.0000`，即**它们全落在退化点上**；而更早一轮我只扫了 `post_guard` 而固定了它的整除性。**盲区来自测试矩阵的参数选择，不是来自公式推导**。

**修法**：`observation/src/planning.py` 改为 `n_after = int(np.ceil(after_s * fs_hz + 0.5))`。

- 重扫 576 组：最坏 **−0.4634 → +0.0366**，保证成立。
- 代价：行宽最多 +1 格。触发条件 `frac(after_s·fs) = 0 或 > 0.5`。
- 新增 `test_post_guard_margin_is_never_negative`（4 组参数，均取在**无补偿时确实为负**的点：−0.4634 / −0.3634 / −0.3333 / −0.2619）。实测对旧公式**四组全红**、对补偿实现全绿。

## 3. 第二轮复核：核实的 8 类问题

### 3.1 `window_overlap` 的"不受影响"是**行为性错误**

判据确实没变（`starts[i+1] < starts[i] + fast_count`），但**输入变了**：行宽 +1 会让"原本恰好不重叠"的配置开始重叠。最小复现（与复核同一组参数，我已实测）：

```
fs=5000, pre=0.01, post=0.0298, 脉宽=0.01, prf=20   → 行距 = fs/prf = 250 索引
   旧行宽 = ceil(0.0398·5000) + 100 + 1 = 250（= 行距）→ 无重叠
   新行宽 = 251（> 行距）→ window_overlap = [True × 8]
                         + 触发"旧版逐行回波生成器必须拒绝该计划"警告
```

已改 `KNOWN_DEFECTS §1`：写明"判据不变、但行宽 +1 会翻转结果"并附算例。

### 3.2 "+1 触发条件"三处因果写反——并牵出我的计算错误

正确规则（扫描确认）：`frac(after_s·fs) = 0 或 > 0.5` 才 +1；`frac ∈ (0, 0.5]` 不变。

```
after·fs = 150.000  frac = 0.000  → 150 → 151  +1
after·fs = 150.200  frac = 0.200  → 151 → 151  不变
after·fs = 150.500  frac = 0.500  → 151 → 151  不变
after·fs = 150.700  frac = 0.700  → 151 → 152  +1
```

**我一度怀疑"mesh 的 153 与手工算的 152 矛盾"**，查下去发现**是我算错**：`n_pre` 必须含光行时展宽，`ceil((0.01 + 300/c)·5000) = 51`（我漏了 `300/c`，算成 50）。mesh 行宽 153 正确，`after_s·fs = 100.005`（frac≈0.005）→ 不 +1。**复核的解释对，我文档里写的理由（"因 `n_after` 恰为整数"）错**，三处已改为按 frac 判定。

### 3.3 §9 验收期望值过期（2008）

`OBSERVATION_RECEPTION_WINDOW.md` §9 仍写"8 × 251 = 2008"（那是"仅修末列"的中间态），与同文件 §8 的 252 矛盾。已改为 **2016 = 8 × 252**。

### 3.4 `planning.py` 旧注释未同步

`planning.py:265-267` 仍写无 `+0.5` 的公式、并把守护测试写成 `test_reception_window_covers_echo_and_post_guard`。已改为带补偿的公式 + **两条**守护测试名。

### 3.5 δ 值域表述过期

复核说带补偿后 `新−旧 ∈ {1,2}`。我给出**显式反例**：

```
after·fs = 150.5（frac = 0.5）→ ceil(150.5)=151、ceil(151.0)=151 → δ=0
after·fs = 150.2（frac = 0.2）→ 151 与 151                       → δ=0
```

故 δ=0 仍可能出现。已把两处"实测 δ∈{0,1,2}"改为方向性结论 **δ ≥ 0** 并给出 frac 判定，不再给依赖网格、不可复现的值域。

### 3.6 observation 侧测试也没迁移

### 3.7 新守护测试"只守 4 个点"（测试作用域问题）

**变异实验**（我自己做的，证明复核说得对）：

```
把 +0.5 改成 +0.25  →  原 57 条测试全部通过（绿）
但同一实现扫描的最坏缺口 = −0.1644 个采样  → 保证已被破坏
```

**修法**：新增网格断言 `test_post_guard_margin_grid_never_negative`（`fs × pre × post × prf = 4×3×4×3 = 144` 组，取最坏 gap 断言非负）。实测：对 `+0.25` 变异**变红**、对 `+0.5` 全绿。

## 4. 复核中我**未采纳**的三条

| 复核的说法 | 我的判断与依据 |
|---|---|
| "头侧 `n_pre` 没做同样补偿，最坏首格缺口 −0.5，而测试把它当普遍成立" | **不是缺陷**。头侧保证方向相反（要求窗起点比最早回波**早**至少 `pre_guard`），而 `n_pre ≥ before_s·fs` 结构上保证保护只多不少；测试断言的就是这个方向。唯一例外是单站切换把窗推后，此时有专门的警告。复核后来也自行更正 |
| "`row_valid` 的断言是恒真空转" | **只对一半**。在 `q_off = max(starts) + fast_count` 下确实恒真，但把 `q_off` 改回物理式 `ceil` 的变异会让它们变红——它们守的是 `q_off` 公式。真正的盲区在 `n_after`，已由 §3.7 的网格断言覆盖 |
| "带补偿后 δ ∈ {1,2}" | **不成立**，有 δ=0 的显式反例（见 §3.5） |

## 5. 我自己在这两轮暴露的问题

1. **文档里写了未经验证的因果**。我写"mesh 因 `n_after` 恰为整数保持 153"，而没把 `n_pre` 的完整公式跑一遍（漏了光行时展项），导致一度反过来怀疑正确的 153，并把错误理由写进三处文档。**教训：写"为什么"时必须把该量的完整公式实测一遍，不能沿用上一轮的手算。**
2. **断言作用域小于结论作用域**。我用 4 个参数点去守一条"保证"，而变异实验证明 4 个点挡不住 `+0.25`（最坏缺口回到 −0.1644）。**教训：守护一条不等式，断言必须扫一片参数区并取最坏值，而不是挑几个已知为负的点。**
3. **把"判据不变"当成"结果不变"**。`window_overlap` 的判据确实没改，但行宽是它的输入之一，+1 会翻转结论——我把"代码没动这一行"误当成"行为不受影响"。**教训：改动行宽/采样网格这类"共同输入"时，要沿每个消费者检查一遍，而不是只看直接改动的那个量。**
