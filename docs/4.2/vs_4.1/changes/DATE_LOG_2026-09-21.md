## 1. Chirp 末列与产物行宽契约

### 问题

旧 `plan_reception` 把半开 ADC 窗右端设在「最晚回波尾沿 + 后置保护」向上取整的索引上，最后一行末格恰好落在右端点外，被丢掉。4.2 已把公式改成 `n_after = ceil(after_s·fs + 0.5)`、`q_off = max(starts) + fast_count`。缺的是：**修复前 251 列产物与当前 252 列计划可以分别加载成功**，pipeline / GUI 预览 / inversion 入口没有交叉核对。

### 修改

- `pipeline.validate_observation_echo_contract`：chirp 核对脉冲数、行宽、`fast_time_s`、`row_start_sample`、metadata 行宽，以及可用时的 observation SHA-256；CW 一维轴不走二维行宽检查。
- 根 pipeline 在 inversion 前、GUI 在 inversion 与回波预览前调用同一契约；不兼容则不启动进程、不打开预览。
- 预览每次从当前 run 重新校验 NPZ，不能用旧 HTML 缓存绕过。
- 「运行全部」在 observation 成功、echo 校验失败时恢复运行按钮，不留假运行状态。
- 新 echo 写入 `artifact_contract_version`、`observation_info_sha256`；chirp 另写 `fast_sample_count`。加载 observation 前后各算一次 SHA-256，中途文件变化则失败。
- inversion 加载器在新 metadata 存在时要求 `fast_sample_count == iq.shape[1]`。
- `test_post_guard_margin_is_never_negative` 真正使用闲置的 `expected_gap`；新增小数位密扫：`+0.5` 通过、削弱为 `+0.4` 失败。

## 2. 运行逻辑收尾

### 2.1 自定义直角坐标仍带可见性字段

**问题**：两端都是 `static`/`linear` 时本地地平没有定义，配置里的高度角、采样步长、「允许不可观测」没有物理含义；混合测站若写了笛卡尔一侧的接收高度角，也会误约束。

**修改**：`normalize_observation_config` 拒绝自定义直角坐标上的无意义 `visibility` 字段，混合测站只拒绝没有本地地平那一侧的高度角。`campaign_planning` 对双直角坐标使用完整 campaign 区间，并区分 `visibility_applicable` 与 `visibility_computed`。GUI 预览：灰色斜纹只表示「本应计算可见性但本次失败」；直角坐标即使位置查询失败也不画斜纹。

### 2.2 `pulse_batch_size=1` 绕开 CUDA OOM 退避

**问题**：网格路径在批量为 1 时退回逐脉冲参考路径，pair/facet 缩块不再发生。

**修改**：存在 `batch_kernel` 时批量 1 仍走该内核。点目标没有该内核，不适用。测试断言 batch=1 仍调用 `_gather_chirp_sample_pairs`。

### 2.3 `fast_sample_count=4.9` / `true` 被截成整数

**问题**：缺省构造 `row_valid` 时 `int(4.9)`→4、`int(true)`→1。

**修改**：`echo/src/geometry.py` 用精确整数检查，拒绝布尔和非整浮点。

### 2.4 文档 δ 与 `window_overlap` 口径错误

**问题**：行为文档和两份 DATE_LOG 把**行宽增量** `{0,1}` 写成窗尾推迟量 δ，并声称 δ 可为 0；选时文档仍写行宽 +1 后 `window_overlap`「判定不受影响」。

**修改**：`OBSERVATION_RECEPTION_WINDOW.md` 与 `OBSERVATION_TIME_SELECTION.md` 改为：恒定 $S_i$ 时 δ ∈ {1,2}；行宽增量单独写；`window_overlap` 判据不变，但行宽是输入，+1 会把「行宽恰好等于行距」翻成重叠。两份 DATE_LOG **不回写正文**，只在文首勘误。`KNOWN_DEFECTS.md` 中 CW 行轴字段数改为 12。符号表 $n_{\mathrm{after}}$ 补 `+0.5`。`adc_window_duration_s` 写入 `PROJECT_OVERVIEW.md` / `GLOSSARY.md`。

### 2.5 T1 网格守护偏疏

**问题**：144 组网格在补偿削弱到 0.45 时仍全绿，守不住 0.013～0.063 采样的缺口。

**修改**：保留解析下界 `fast_sample_count >= n_pre + after_s·fs + 1.5`；补充经 `plan_reception` 的小数位密扫，以及 `target.extent_path_m>0`、多 Run。

### 2.6 `Spin` 缓存键

**问题**：改已有实例的周期/初相位/自转轴可能不失效。

**修改**：缓存键含设备、初相位、周期和自转轴（记入 `KNOWN_DEFECTS.md` §4，见运行逻辑收尾）。

## 5. 波形从属重构

### 问题

GUI 把「发射波形」放在全局按钮，实现却把 `waveform.type` 以及 PRF/脉宽写在 `observation.waveform`。独立跑 observation 时波形字段本不应合法；射频类型、带宽、幅度属于 echo。曾尝试「type 只写在 observation、echo 镜像」——这把从属关系说反了，已撤回。

### 修改

**落盘**

- Chirp：`schedule` + `observation.transmit.{prf_hz,pulse_width_s}` + `radar_system` + `receiver_sampling`
- CW：`receive`；不得出现 `observation.transmit`
- 射频类型只写 `echo.waveform.type`，必须与事件源一致（Chirp↔`schedule`，CW↔`receive`）
- 旧 `observation.waveform`：**拒绝**，中文说明迁到 `transmit` 与 `echo.waveform.type`，不静默改写

**代码**

- `observation/src/config_normalize.py`：顶层允许 `transmit` 不允许 `waveform`；事件源由 `schedule` XOR `receive` 决定。
- `observation_info.py` / `campaign_planning.py`：脉冲时序读 `transmit`。`planning.py` 的 Python API 仍接收 `{prf_hz, pulse_width_s}` 映射（参数名仍为 `waveform`，不是用户 JSON）。
- `pipeline.py`：缺 `echo.waveform.type` 时可按事件源补上；两边不一致则失败。`prepare_run` 先深拷贝调用方配置，补 type 不改调用方内存。空字符串 type 视为未填。
- GUI：全局组合框只写 `echo.waveform.type` 并切换事件源；「发射时序」卡片绑定 `observation.transmit.*`。`collect` / 载入遇到 `observation.waveform` 报废弃错误，不 `pop()` 掉 PRF。

**夹具与文档**

- `configs/chirp_point_target_test.json`、`chirp_mesh_target_test.json`、`point_target_debug.json`：observation 段改为 `transmit`，type 留在 echo。
- `DEFAULT_CONFIG` 去掉 `observation.waveform`。
- 4.2 概况、架构、术语表、选时/接收窗公式中的 `waveform.pulse_width_s` 改为 `transmit.pulse_width_s`；GUI 手册写明全局按钮的从属。
