# Chirp 网格回波跨脉冲批处理（阶段 B）

> 状态：已在 4.2 实现并完成完整 60000 脉冲实测。阶段 A 的低风险优化见 `ECHO_SIMULATION_PERFORMANCE_PHASE_A.md`。

## 1. 语义边界

阶段 B 只改变网格 Chirp 核函数的计算组织，不改变观测计划、物理模型或输出契约。每个 Run 仍先建立唯一全局 ADC 整数索引 `q_values`；所有与同一索引相交的脉冲贡献先求和，再按 `row_start_sample` 映射为二维 `[pulse, fast_time]` 保存行。真实回波重叠时保留所有脉冲贡献，保存行重叠仍只是同一 Run 级信号与噪声的共享视图。

`centroid_compensated`、`raw_baseband`、`per_pulse_linear` 和 `frozen` 的时间、路径与相位公式未改变。时间、旋转相位和路径中间量继续使用 `float64`；网格配置为 `float32` 时，最终贡献和输出仍为 `complex64`。

## 2. 实现

Run 内候选脉冲按 `pulse_batch_size` 分组。每组按脉冲主序构造扁平的 `(pulse_index, q_index, dt)` 列表，避免不同脉冲候选样点数不同所需的填充。内核随后按“样点对块 × 面元块”计算：

1. 每个样点对使用自己的脉冲索引读取接收视线、发射视线、公共路径、路径率和散射时标；
2. 面元位置与法向也按 `facet_chunk_size` 分块旋转，使该参数真正约束批处理峰值显存；
3. 照明、接收权重、差分路径、Chirp 包络和载波相位在整个样点对块上向量化；
4. 每个批次只把最终复数贡献传回 CPU 一次，按原脉冲顺序用 `numpy.add.at` 累加到 Run 的唯一 `q_values`。

没有使用 CUDA `scatter_add_` 处理重复索引，因为其原子累加顺序可能使固定输入在 GPU 上产生不确定的末位差异。当前归并顺序与逐脉冲参考一致，且跨批次边界的物理重叠仍会相加。

## 3. 计算策略与显存

新增 `pulse_batch_size`，默认值为 32。它与 `facet_chunk_size`、`fast_sample_chunk_size` 一样只控制计算策略，不进入物理模型；设为 1 时使用原逐脉冲参考路径。

`fast_sample_chunk_size` 在批处理路径中表示一次处理的扁平“脉冲—ADC 样点”对数，`facet_chunk_size` 表示一次处理的面元数。CUDA OOM 发生时，尚未归并的当前批次会被完整重试：先缩小样点对块，再缩小面元块；框架还可缩小脉冲批量。已归并结果不会重复累加。

输出元数据记录请求/实际批量、实际最小样点对块和面元块、OOM 重试次数、峰值设备内存以及确定性归并方式。

## 4. 正确性验收

自动化测试覆盖两个输出参考、两个脉内运动模型、CPU float32/float64、可用时的 CUDA float32、固定种子噪声、保存行共享 ADC 索引、跨批次物理重叠、路径上限异常和非法块大小。

验收结果：

- `echo/tests/`：26 项通过；
- 根目录 `tests/`：75 项通过；
- 真实计划 2 Run × 3 脉冲，批量 1 与批量 3 的 `clean_iq`、`iq` 最大复数差均为 0，`valid` 完全相同；
- 完整旧产物与阶段 B 产物比较，`clean_iq`、`iq` 最大复数差均为 `3.332000986e-08`，`valid`、`row_start_sample`、`signal_echo_overlap` 和 `window_overlap` 完全相同。

该完整差值小于 complex64 的受控舍入尺度，未出现样点位置、相位约定或贡献数量变化。

## 5. 性能验收

环境为 NVIDIA GeForce RTX 2060 Max-Q、PyTorch 2.3.1、CUDA 11.8、float32、1280 面元。基准均先预热并在同一进程内重复。

1 Run × 120 脉冲、`facet_chunk_size=1280`、`fast_sample_chunk_size=1024`：

- 逐脉冲参考：最小 0.35 s，2.90 ms/脉冲，峰值 17.1 MiB；
- 批量 32：最小 0.25 s，2.11 ms/脉冲，峰值 189.6 MiB；
- 批量 64：最小 0.25 s，2.09 ms/脉冲，继续增大批量收益已经很小。

Profiler 的 60 脉冲结果：

- 逐脉冲参考：19146 次 CUDA kernel，约 319 次/脉冲；
- 批量 32：1593 次 CUDA kernel，约 27 次/脉冲；
- kernel 调用总量减少约 12 倍。

50 Run × 24 脉冲的真实 Run 结构基准：

- 逐脉冲参考：3.55 s，2.96 ms/脉冲；
- 批量 32：2.43 s，2.03 ms/脉冲；
- 批处理本身提供约 1.46 倍加速。

完整 `60000 × 153` 输出、1280 面元、批量 32、1280/1024 块的计算与保存耗时为 126.48 s，峰值设备内存 203109888 B（约 193.7 MiB），没有触发 OOM 退避。与阶段 A 前同一作业的 944.06 s 相比，阶段 A 与阶段 B 合计约加速 7.46 倍。

另以默认 256/256 块运行完整批处理作业耗时 174.53 s，说明跨脉冲批处理不能替代合理的面元与样点对分块配置。

## 6. 后续可选项

批处理已经把主要问题从“每脉冲数百个小 kernel”降低到约 27 次/脉冲。`torch.compile`、CUDA Graph 或自定义融合核没有纳入 4.2 阶段 B：它们会引入动态图形、编译缓存或平台专用维护成本，应在新的 profiler 证据表明收益足以覆盖复杂度后单独评估。不得为了进一步加速而无分析地降低时间或路径精度。
